Figure 3.3(a) — Detailed Use Case Diagram for Registration

Registration is separate from login and includes the name, email, password and validation requirements.

Actor association «include»: required behavior «extend»: conditional behavior

Required input and validation use «include». Successful registration creates the account only when the details are valid and the email is available. Failure displays an error and creates no account. These conditional outcomes use «extend», pointing back to Register.

Figure 3.3(b) — Detailed Use Case Diagram for Shared Login and Logout

User and Admin share the same Login use case with email and password. Both roles can recover a forgotten password. Successful login creates a session; either role can log out to end its current session.

Actor association «include»: required behavior «extend»: conditional behavior

User and Admin share Login and Forgot Password. Login includes entering email and password and validating credentials. Forgot Password extends Login when recovery is selected; the detailed reset process is covered in Figure 3.12 of the report. Login Success includes creating an authenticated session and opens the area allowed by the account role. Invalid credentials produce an error without creating a session. A successful password reset revokes existing sessions for either role; the account must log in again. User and Admin each connect directly to the same Logout use case. Logout includes End Current Session and requires an authenticated session. Logout has no include or extend relationship with Login. Registration remains separate.
